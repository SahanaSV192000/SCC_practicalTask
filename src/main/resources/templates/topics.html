DevOps Practices

DevOps combines development and operations so teams can deliver software quickly, reliably, and safely.

  • Encourage collaboration between development and operations.
  • Automate repetitive tasks.
  • Use shift-left testing to find defects earlier.
  • Continuously improve through feedback and retrospectives.
Plan → Build → Test → Release → Improve
Source Control and GitHub

Git records application changes and GitHub provides collaboration, pull requests, reviews, and repository management.

  • Create short-lived feature branches.
  • Use clear and meaningful commit messages.
  • Open pull requests for code review.
  • Protect the main branch with review and build rules.
Feature Branch → Commit → Pull Request → Review → Merge
CI/CD and Jenkins

Continuous integration automatically validates every code change. Continuous delivery prepares successful changes for deployment.

  • Trigger Jenkins when code is pushed to GitHub.
  • Compile the application and run unit tests.
  • Create a build artifact such as a JAR file.
  • Stop the pipeline when a quality gate fails.
GitHub Push → Jenkins → Test → Build JAR → Deploy
Containers and Docker

Docker packages the application and its runtime requirements into a portable image.

  • Use a suitable and small base image.
  • Build images using a Dockerfile.
  • Tag images with a version number.
  • Never store passwords or secrets in an image.
Java Code → Dockerfile → Image → Registry
Kubernetes

Kubernetes manages containers and keeps the desired number of healthy application instances running.

  • Deployments manage replicas and rolling updates.
  • Services provide stable network access.
  • ConfigMaps store non-sensitive configuration.
  • Secrets store sensitive configuration.
  • Readiness and liveness probes verify application health.
Deployment → Pods → Health Checks → Service
Infrastructure as Code

Infrastructure as Code defines infrastructure using version-controlled files instead of manual console changes.

  • Use variables for environment-specific values.
  • Use outputs to expose useful resource information.
  • Use modules to reuse infrastructure patterns.
  • Protect Terraform state from accidental changes.
Terraform Code → Plan → Review → Apply
Cloud Basics

AWS provides compute, networking, storage, identity, and security services that can host the delivery platform.

  • EC2 provides virtual servers.
  • VPC provides network isolation.
  • S3 provides object storage.
  • IAM controls access to AWS resources.
  • Security groups act as virtual firewalls.
User → VPC → Security Group → EC2
Security

Security should be included throughout the delivery lifecycle rather than added only before production.

  • Scan dependencies for known vulnerabilities.
  • Scan container images before deployment.
  • Use least-privilege IAM access.
  • Store secrets outside source code.
Code → Dependency Scan → Image Scan → Secure Deploy
Observability

Observability helps engineers understand system behavior using logs, metrics, dashboards, and alerts.

  • Logs explain individual events.
  • Metrics show trends and system health.
  • Dashboards present important signals.
  • Alerts notify the responsible team when action is needed.
Application → Logs and Metrics → Dashboard → Alert
Troubleshooting

Troubleshooting should be evidence-based. Start with the symptom, inspect logs and events, test a hypothesis, and document the result.

  • Check Jenkins console output for pipeline failures.
  • Check Kubernetes pod status and events.
  • Read application logs before changing configuration.
  • Write a blameless root-cause analysis.
Symptom → Evidence → Hypothesis → Fix
Release Management

Release management provides a controlled process for versioning, deploying, communicating, and recovering from application changes.

  • Use consistent version numbers.
  • Write release notes.
  • Choose rolling, blue-green, or canary deployment strategies.
  • Prepare a rollback plan before deployment.
Version → Release Notes → Deploy → Verify → Rollback if Needed
Documentation

Documentation makes operational knowledge available to the whole team during deployments, incidents, and handovers.

  • Maintain deployment notes.
  • Write runbooks for common incidents.
  • Record incident timelines and root causes.
  • Update documents after every failure drill.
Document → Share → Operate → Improve
